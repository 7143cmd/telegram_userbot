# Логіка взаємодії ботів та зміна тематики

У цьому документі детально описано алгоритми та сценарії взаємодії юзерботів між собою та з реальними користувачами.

---

## 1. Загальний цикл взаємодії (Bot-to-Bot)

1. **Слухач подій:** Усі боти-учасники слухають нові повідомлення в цільових групах.
2. **Блокування стану (`asyncio.Lock`):** Коли надходить нове повідомлення, один із ботів перехоплює його під блокуванням `group_state.lock`, щоб уникнути дублювання відповідей.
3. **Вибір наступного спікера:**
   * Автор останнього повідомлення виключається із кандидатів (аккаунт не пише сам собі).
   * Ігноруються боти, які відповідали нещодавно (історія `recent_speakers`).
   * Із залишкового списку випадковим чином (`random.choice`) обирається наступний бот.
4. **Імітація людської поведінки:**
   * Витримується випадкова затримка (`min_random_cooldown` .. `max_random_cooldown`).
   * Вмикається статус `typing...`, тривалість якого динамічно розраховується від довжини згенерованого тексту.
5. **Генерація та відправка:** Бот робить запит до LLM з урахуванням ролі (ім'я, стать) та надсилає відповідь у чат, передаючи естафету наступному боту.
